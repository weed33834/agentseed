# 验证清单

> 护栏的可执行版本。任何编程任务收尾时跑一遍。灵感来源：SFD Lab 五步清单、
> DevelopersGlobal 防幻觉（风险分级 + 验证分层）、CDV 双通道验证、
> reze83 先验证后声称规则。

---

## 阶段 0 —— 风险分级（开始前）

给任务输出定级：
- **关键（Critical）** —— 输出错误会造成伤害（被执行代码、法律、金融、医疗）。
- **高（High）** —— 输出错误浪费大量精力（大型重构、部署）。
- **中（Medium）** —— 输出错误烦人但可恢复。
- **低（Low）** —— 外观层面。

关键/高风险走全套；中/低风险做轻量检查。

- [ ] 实现开始前已确定风险等级。

## 阶段 1 —— 契约检查（写码前）

- [ ] 我能用一句话陈述契约（行为 / 接口 / 范围）。
- [ ] 没有默默吞进假设——未知项是问来的，不是猜的。
- [ ] 目标接口存在，或已明确提出待批准。

## 阶段 2 —— 实现卫生

- [ ] 没有用 stub / mock / fake / placeholder / dummy / TODO / FIXME 充当逻辑。
- [ ] 每个被调用的符号都在本项目内被定义或导入。
- [ ] 每个外部 API 都对照**已安装版本**（锁文件）核查过，而不是最新版文档。
- [ ] 无死代码：每条语句的结果都被消费。
- [ ] 安全底线：输入校验、无 SQL 注入/XSS 模式、无硬编码密钥。

## 阶段 3 —— 执行证据（硬闸门）

- [ ] 我运行了测试套件，可粘贴命令 + 输出。
- [ ] 我端到端运行了代码（不是部分路径）。
- [ ] 部署/服务层已确认在运行（若声称）。
- [ ] 本轮引用过的文件都已重读；无过期文件断言。
- [ ] 需要运行代码证实的声明已通过 `sandbox_run` 实证。
- [ ] 结构化输出已通过 `schema_validate` 校验。
- [ ] `verify_code` → `suspects` 为空。
- [ ] `scan_hallucination` → `clean: true`（无 stub/夸大/虚构命中）。

## 阶段 4 —— 语言审查（最终答复）

- [ ] 每句陈述为 OBSERVED，或标注为 INFERRED。
- [ ] 无证据时不使用夸大词汇：
      guaranteed / definitely works / all tests pass / everything works /
      fully tested / production ready / no bugs / works perfectly /
      should work / trust me。
- [ ] 不确定性被如实表达（"我需要先检查 X"、"我不确定"），绝不掩盖。
- [ ] 引用、链接、统计数字真实且有出处。

## 阶段 5 —— 降级规则

关键/高风险的任何一项未勾选，任务即**未完成**。降级为"进行中"，明确报告
哪些检查失败，列出剩余工作。绝不悄悄标记完成。

### 快速闸门（聊天类非代码答复）

1. 读者能否仅凭我提供的内容核实我的关键论断？
2. 我引用了任何我并未真正见过的东西吗？
3. 我是否诚实地表达了不确定性？
4. 我编造了任何数字、名称、链接或政策吗？
