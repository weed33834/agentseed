# 検証チェックリスト

> ガードレールの実行可能版。コーディングタスクの最後に実行する。
> 出典：SFD Lab 5 ステップ、DevelopersGlobal（リスク分類 + 検証レイヤー）、
> CDV 二重チャネル、reze83 先検証ルール。

---

## フェーズ 0 — リスク分類（開始前）

出力リスクを分類：
- **Critical** — 誤出力が危害を引き起こす（実行コード、法律、金融、医療）。
- **High** — 誤出力が大きな労力を浪費（大型リファクタ、デプロイ）。
- **Medium** — 面倒だが回復可能。
- **Low** — 外観のみ。

Critical/High は全検査、Medium/Low は軽量チェック。

- [ ] 実装開始前にリスククラスを決定した。

## フェーズ 1 — 契約チェック（コード作成前）

- [ ] 契約を 1 文で述べられる（挙動 / インターフェース / 範囲）。
- [ ] 暗黙の仮定を飲み込んでいない — 不明点は質問した、推測していない。
- [ ] 対象インターフェースが存在するか、承認のため明示的に提案されている。

## フェーズ 2 — 実装衛生

- [ ] stub/mock/fake/placeholder/dummy/TODO/FIXME をロジックの代用にしていない。
- [ ] 呼ぶ全シンボルがこのプロジェクトで定義・インポートされている。
- [ ] 外部 API は**インストール版**（ロックファイル）で確認した（最新ドキュメントではない）。
- [ ] デッドコードなし：各文の結果が消費されている。
- [ ] セキュリティ基本：入力検証、SQL インジェクション/XSS パターンなし、ハードコード
      シークレットなし。

## フェーズ 3 — 実行証拠（ハードゲート）

- [ ] テストスイートを実行し、コマンド + 出力を貼れる。
- [ ] コードをエンドツーエンドで実行した（部分パスではない）。
- [ ] デプロイ/サービス層が実際に稼働していることを確認した（主張する場合）。
- [ ] 今ターンで引用するファイルを再読した（古いファイル主張なし）。
- [ ] 実行を伴う主張は `sandbox_run` で実証した。
- [ ] 構造化出力は `schema_validate` で検証した。
- [ ] `verify_code` → `suspects` 空。
- [ ] `scan_hallucination` → `clean: true`。

## フェーズ 4 — 言語監査（最終回答）

- [ ] すべての記述が OBSERVED、または INFERRED とラベル付け。
- [ ] 証拠なしの誇大語彙なし：guaranteed / definitely works / all tests pass /
      everything works / fully tested / production ready / no bugs /
      works perfectly / should work / trust me。
- [ ] 不確実さを正直に表現（「X を確認する必要があります」）、隠さない。
- [ ] 引用・リンク・統計は実在し、帰属可能。

## フェーズ 5 — 格下げルール

Critical/High で**一つでも未チェックならタスクは未完了**。「進行中」に格下げし、
どのチェックが失敗したかを正確に報告し、残作業を列挙する。黙って完了にしない。

### クイックゲート（チャット型・非コード回答）

2. 実際に見ていないものを引用していないか？
3. 不確実性を正直に表現しているか？
4. 数字・名前・リンク・政策を捏造していないか？
